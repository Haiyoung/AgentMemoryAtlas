本文针对大语言模型代理在长程场景中记忆机制扁平化、缺乏逻辑关联的问题，提出了一种名为 CompassMem 的事件中心型记忆框架。核心价值在于引入认知科学中的事件分割理论，将记忆组织为具有显式逻辑关系的事件图谱，而非简单的文本片段集合。差异化优势在于将记忆访问从浅层语义匹配升级为基于逻辑地图的结构化导航。关键结论表明，该方法在 LoCoMo 和 NarrativeQA 数据集上能提升检索与推理性能，但具体提升幅度因原文截断暂无法量化。

## 四、核心问题与解决方案
### 4.1 待解决的核心问题
1. **领域级根本问题**：代理在长程任务中难以有效保留、组织和检索过去经验以支持决策。
2. **现有方法痛点**：记忆存储多为扁平化文本片段；缺乏经验单元间的逻辑关系（如因果、时序）；记忆访问依赖浅层语义匹配，脱离结构。
3. **工程落地卡点**：现有记忆系统多为静态存储，无法作为主动组件引导推理过程。

### 4.2 核心解决方案
- 理论框架：基于事件分割理论（Event Segmentation Theory）。
- 核心架构：CompassMem 框架，将记忆组织为事件图谱（Event Graph）。
- 关键技术：增量式经验事件分割、显式逻辑关系链接、基于图谱的结构化导航。
- 创新机制：记忆作为逻辑地图（Logic Map），支持超越表面检索的目标导向导航。

### 4.3 核心优势（量化 + 定性）
1. 性能优势：在多个骨干模型上一致提升检索和推理性能（具体数值原文未提及）。
2. 效率优势：通过结构化导航减少无关记忆干扰，提升推理针对性。
3. 工程优势：模块化设计，可增量更新事件图谱，适应动态环境。

## 五、方法与技术架构
### 5.1 核心架构设计
> 文字描述 + 架构图（Mermaid/图片）

CompassMem 架构核心在于将代理的经验流转化为事件图谱。系统首先对交互经验进行增量式事件分割，然后将分割后的事件作为节点，通过显式的逻辑关系（如因果、时序）连接成边。代理在推理时，不再直接检索文本块，而是在该逻辑地图上进行结构化导航，逐步收集有价值的记忆。

```mermaid
graph LR
    UserEnv[用户与环境交互] --> Experience[原始经验流]
    Experience --> Segment[增量事件分割模块]
    Segment --> EventNode[事件节点]
    EventNode --> Link[逻辑关系链接]
    Link --> EventGraph[事件图谱记忆库]
    Agent[智能代理] --> Navigate[结构化导航检索]
    EventGraph --> Navigate
    Navigate --> Reasoning[长程推理与决策]
```

### 5.2 关键技术实现细节
| 技术模块 | 实现路径 | 工程注意事项 |
| -------- | -------- | ------------ |
| 事件分割模块 | 基于事件分割理论，识别经验流中的边界 | 需平衡分割粒度，避免过碎或过粗 |
| 图谱构建模块 | 提取事件间因果与时序关系，建立边连接 | 关系提取准确性直接影响推理质量 |
| 导航检索模块 | 在图谱上进行目标导向的路径搜索 | 需防止图谱搜索陷入局部最优或循环 |
| 依赖组件 | 大语言模型骨干、图谱数据库 | 需优化图谱查询延迟以匹配实时交互 |

### 5.3 架构优缺点
- 优点：显式捕捉逻辑关系，支持复杂推理；记忆结构清晰，可解释性强。
- 缺点：图谱构建与维护开销较大；对事件分割的准确性依赖度高。
